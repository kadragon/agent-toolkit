## Harness — `task-*` edge enforcement (rescoped)

Source: `docs/design/task-graph-audit.md`, re-scored in `docs/design/harness-altitude-audit.md`.
Each edge is scored on three questions — **Silent** (invisible to the orchestrator at its next
decision point), **Costly** (damage survives the session: lands on `main`/remote, corrupts tracked
state, or burns a resource a re-run does not reclaim), **Decidable** (a file or exit code settles
it). 3/3 ships; 2/3 ships only if the residual failure is unbounded; 0–1/3 is ceremony.

### Cut — do not re-file without new evidence

Re-filing requires evidence of the specific kind each item failed on, not a restated intuition:

- **commit-guard merge coverage** — cut at ≈1/3 after scoring, which is what the item itself asked for before any build. Both named sites were read, and neither is a mistake to catch. (1) `merge-and-cleanup.sh:86–89` runs its `git merge --ff-only FETCH_HEAD` only inside `if [ "$MERGE_OK" = "true" ]` — the remote PR merge has already landed — and immediately after `git fetch origin "$BASE_BRANCH"`, so it fast-forwards local `main` onto a commit that is already on the remote. A separate marker avoids that only by adding a second opt-in surface to maintain. *Silent* and *Costly* therefore rest on a hypothetical third site; only *Decidable* holds outright. ## Harness — `task-*` cycle latency

Source: latency measurement of 2026-08-19, recorded here so no run re-derives it. GitHub Actions
`harness-check` completes in 13–22s across the last 25 runs, so **CI is not the bottleneck**. PR
create→merge is ~3–17 min (median ~10 min), and that window is almost entirely
`task-review-cycle` Step 2 (review panel) plus Step 3 (verifier + contest agents). One non-trivial
cycle runs **four sequential agent waves** — implement → `qa-verifier` → 3-source panel →
verifier/contest — and the panel's wall clock is `max()` of its three sources, not the sum. Recent
merged PRs run 5–28 files and +8/-7 to +720/-20; median ≈9–13 files, ≈50–100 lines.

Ordered so the isolated, low-risk items land before the Step 2 restructure they would otherwise
conflict with.

- [ ] **Cache `preflight.sh` output per cycle** — `task-review-cycle/SKILL.md` re-runs `preflight.sh` in 7 separate blocks (~1.7s each) and re-resolves `SKILL_DIR` 9 times, purely so each block reads standalone. Write the JSON once at Setup to a path under `$(git rev-parse --git-dir)` and have later blocks read that file, falling back to a live run when it is absent. Keeps every block runnable on its own without paying for a fresh probe.
- [ ] **Re-cut the trivial short-circuit on line delta and apply it to the whole panel** — the gate at Step 2-1 (`FILE_COUNT ≤ 3` AND `LINE_DELTA ≤ 10` AND no `SECURITY_HIT`) skips only the Claude slot; agy (2-2) and Codex (2-3) run unconditionally. Of the last 15 merged PRs exactly one (#236) cleared it, because this repo's changes are wide-and-shallow mechanical sweeps (#234: 16 files, +48/-51). Re-express the gate primarily on `LINE_DELTA` with a threshold that actually fires on that shape, and make it gate the panel rather than one slot — the security escalation stays an absolute override. Record the skipped engines in the consolidation table as today.
- [ ] **Quorum-and-go on the review panel** *(blocked by: trivial-short-circuit)* — the panel finishes at `max()` of three sources; `agy-review.sh` alone allows `--print-timeout 9m`, and the per-source budget was just raised 600s→1200s (#237), lengthening the tail further. Replace "wait for all three, then proceed" with "proceed once 2 of 3 have returned AND a minimum elapsed floor has passed", recording the outstanding source exactly like a timeout. Preserves panel breadth in the common case and cuts only the tail.
- [ ] **Run QA in parallel with the review panel** *(blocked by: quorum-and-go)* — `qa-verifier` is its own blocking wave in front of the panel in both `task-new` and `task-next` Step 3, so the panel cannot start until contract QA has finished. Commit and open the PR right after implement, then launch `qa-verifier` in the same turn as 2-1/2-2/2-3 and fold its contract findings into the Step 3 consolidation table as a fourth source. Version bump and pre-merge cleanup move into the Step 5 commit. Four waves become three. The independence rule is unchanged: whoever implemented still never verifies.
- [ ] **Batch the pre-implementation human gates** — a non-trivial cycle can stop for the Step 1/2 candidate pick, the Step 2.5 batch nudge, the Step 2.5 lite-path offer and the plan-mode approval, each a separate round trip of idle wall clock. Merge the candidate pick and the Step 2.5 offers into a single `AskUserQuestion`, and carry the drafted Sprint Contract into `ExitPlanMode` so approval is one action. Non-interactive defaults are unchanged.
- [ ] **Trim `task-next`/`task-new` SKILL.md to references** *(blocked by: qa-in-parallel, batch-human-gates)* — `task-next/SKILL.md` is 37KB and `task-review-cycle/SKILL.md` 30KB, re-prefilled on every turn of every cycle. The absent-role fallback prose is restated at each of the three spawn points in both skills, the roster-check block is duplicated across them, and `## Edge cases` is ~80 lines that a typical run never reaches. Move the rarely-hit branches into `references/` the way batch/tree mode already are, leaving the hot path in `SKILL.md`. No behavior change — this is a token cut.
