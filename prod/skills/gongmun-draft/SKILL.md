# 발신 문서 초안 작성

노트·원문 문서를 근거로 대외 발신 문서 본문을 쓰는 절차.
수신·발신·문서번호는 전자문서 시스템이 자동 생성하거나 사용자가 직접 입력하므로 **제목 + 본문**만 작성한다.

## 공통 규칙

- **제목 + 본문만** 쓴다.
- **모든 주장은 노트나 원문 문서에서 확인된 사실로 닫는다.** 근거를 못 찾은 문장은 쓰지 말고 사용자에게 묻는다.
  회신에서 지어낸 날짜·조건 하나가 대외 약속이 되기 때문이다.
- **들여쓰기:** depth 한 단계 내려갈 때마다 앞 공백 2칸씩 추가.
  `1.`(0칸) → `가.`(2칸) → `1)` 또는 `-` 불릿(4칸) → `가)`(6칸).
  `-` 불릿도 상위 라벨(`가.` 등)의 하위이므로 2칸 더 들여쓴다.
- **관련 문서 표기:** `{부서명}-{문서번호}({YYYY. M. D.}) "{공문 제목}"`. 날짜 없이 번호만 쓰지 않는다 —
  부서가 매년 번호를 초기화하므로 날짜 없이는 다른 해의 같은 번호 문서와 구분되지 않는다.
  날짜 변환: `2026-05-12` → `2026. 5. 12.`(월·일 앞 0 제거, 점 뒤 공백).
- **기관장 결재 표기:** `관련`에 인용하는 공문이 기관장 결재 문서면 공문명 뒤에 결재권자를 붙인다 —
  예: `기획과-2765(2026. 9. 22.) "2026학년도 OO 사업 계획 수립"<총장결재>`.
  결재권자를 알 수 없으면 붙이지 말고 사용자에게 묻는다.

## Step 1: 원문 확정

받은 공문·메일·질의 원문을 Read하고, 상대의 요구를 항목으로 분해한다.
문서번호·시행일·요구 항목 번호를 그대로 인용할 수 있게 적어 둔다.
안내·협조 요청처럼 받은 원문이 없으면, 사용자가 가리킨 노트에서 알릴 사실(일정·대상·변경 내용)을 항목으로 뽑는다.
노트 경로가 없으면 대화 컨텍스트에서 추론하고, 그래도 없으면 묻는다.

## Step 2: 항목별 답과 근거

회신이 길어지는 대부분의 이유는 묻지 않은 것까지 설명해서다. 상대가 물은 항목에 1:1로 답한다.

각 항목의 답은 넷 중 하나다 — 수용 / 불가 / 조건부 수용 / 확인 필요.
**불가·조건부는 근거(규정 조문·계약 문서·시스템 제약)를 반드시 붙인다.** 근거 없는 거절은
재질의를 부르고, 그 재질의에 답하는 비용이 처음부터 근거를 다는 비용보다 크다.
사용자가 이미 답을 정해 준 항목은 그 판단을 바꾸지 말고 문장만 다듬는다.

## Step 3: 본문 작성

```
{제목 — 상대 요구를 그대로 반영. 예: "OO 사업 OO 요청에 대한 회신"}

1. 관련: {부서·업체명}-{문서번호}({YYYY. M. D.}) "{원문 제목}"
   {메일이면: {YYYY. M. D.} 귀사 메일 "{제목}"}

2. 위와 관련하여, {목적}을 위해 {대상}을 다음과 같이 {회신/제출}합니다.

  가. {요구 항목 1}
    - {수용/불가/조건부} — {근거}

  나. {요구 항목 2}
    - ...

3. {필요 시 기한·후속 조치}.  끝.
```

표기 관례:

- **외부 기관 수신**(타 기관·협의회·정부기관)이면 첫 항목을 `1. 귀 기관의 무궁한 발전을 기원합니다.`로
  두고 이후 번호를 하나씩 민다(`2. 관련:` → `3. 위와 관련하여, …`). 기관 내부 부서·업체 메일에는 붙이지 않는다.
- 관련 문서가 없으면 `관련:` 항목을 생략하고, `위와 관련하여` 대신 목적 문장으로 시작한다.
- `위와 관련하여` 뒤에는 항상 쉼표, 이어서 `~을 위해 ~을 {제출/회신}합니다.` 형식 — 목적은 **발신 측(우리) 목적**으로 쓴다.
  원문이 밝힌 요청 목적(예: 주최 측의 "원활한 정기총회 준비를 위하여")을 옮겨 쓰지 않는다
  — 행사 참석자 명단 제출이면 `정기총회 참석을 위해`.
- 붙임이 1개면 번호 없이 `붙임  {문서명} 1부.  끝.`, 2개 이상이면 `붙임  1. … 1부.` / `      2. … 1부.  끝.`
  본문 참조도 붙임 1개면 `(붙임)`, 여럿이면 `(붙임 1)`.
- 가/나/다 항목 수는 제한 없다. 단일 항목이면 `가.` 하나만 쓴다.

**문체.** 공문은 `~합니다`체, 업무 메일은 그보다 평이하게 쓰되 판단·근거 문장은 동일하게 남긴다.
상대가 업체면 요구 사항을 **번호로 고정**해 회신 대조가 가능하게 한다.

## Step 4: 문체 감사 (필수 게이트)

초안을 사용자에게 보여 주기 전에 반드시 Skill 도구를 "prod:kr-style"로 호출해 감사를 통과시킨다.

1. 제목 + 본문을 scratchpad 파일로 저장한다.
2. kr-style 루프를 돌린다: 감사 스크립트 실행 → `[FAIL]` 교정 → 수동 체크리스트 → 재실행.
3. **exit 0이 되어야 출력한다.** 오탐(인용한 공문 제목, 공문 관용구 `위와 관련하여` 등)은
   고치지 않고 Step 5에서 한 줄로 알린다.
4. 교정은 표현만 바꾼다 — 사실·날짜·항목 수·판단(수용/불가)은 바꾸지 않는다. 공문 종결 형식
   (`~합니다`, `~함`, `끝.`)은 유지한다.

출력한 초안이 감사를 통과한 최종본이어야 한다. 감사 전 초안을 먼저 보여 주지 않는다.

## Step 5: 확인 사항 보고

초안 출력 후, 사용자가 직접 확인해야 할 항목을 간결히 목록으로 알린다:

- **지어낼 뻔했던 값**(기한·담당자·금액·날짜)은 플레이스홀더(`[확인 필요]`)로 남기고 목록에 적는다.
- 결재권자 표기를 생략한 `관련` 문서
- kr-style 오탐으로 남긴 문구
- 수신처가 2개 이상으로 보이면: 본문은 동일하게 두고 "수신처별 별도 기안이 필요한지 확인 바랍니다" 추가
