# 보고서 작성 규칙

기계 검사가 가능한 규칙은 `scripts/lint_report.py`가 판정한다(규칙 번호 R1~R13). 나머지는 이 문서로 점검한다. 출처는 문서 끝 §9에 있다.

## 0. 작성 원칙

보고서는 읽는 사람이 판단하도록 돕는 문서다. 아래 원칙은 모든 형태·유형에 적용한다.

- **결론 먼저.** 첫 `□`(또는 요약 박스)만 읽어도 결론과 요청 사항을 알 수 있게 쓴다. 검토·결과 보고는 결론을 끝에 숨기지 않는다.
- **요청 사항을 적는다.** 읽는 사람이 "그래서 내가 무엇을 해야 하는가"를 묻지 않게 한다: 결재·승인, 의사결정, 인지(참고) 중 무엇인지 밝힌다.
- **한 보고서에 한 주제.** 주제가 둘이면 보고서를 나눈다.
- **질문이 남지 않게.** 누가·언제·어디서·무엇을·어떻게·얼마로·얼마 동안을 채운다. 빈 항목은 `[확인 필요]`로 남기고 완료 보고에 적는다.
- **근거로 말한다.** "들리는 이야기" 수준의 판단 대신 수치·문서번호·조사 결과를 적는다. 통계는 연도별 추세가 보이게 쓴다.
- **분량.** 1쪽 보고형은 1쪽, 계획서형도 본문은 가능한 짧게 쓰고 세부는 붙임으로 보낸다. 본문만으로 뜻이 통해야 한다. 핵심 내용을 붙임으로만 넘기지 않는다.

## 1. 형태와 유형 판정

**형태**는 지면 구성이고 **유형**은 내용 목적이다. 둘을 따로 정한다.

| 형태 | 식별 | 골격 |
|------|------|------|
| 계획서형 | 표지 + 로마숫자 장 제목(Ⅰ~Ⅴ) | 유형별 골격을 장(Ⅰ~Ⅴ)으로 편다 |
| 1쪽 보고형 | 첫 줄 `<부서, YYYY. M. D.>` | 유형별 골격을 `□` 3~5개로 줄이고, 각 `□`에 `○` 2~3개 |
| 기관 서식형 | 기관이 배포한 양식(세출예산 사업계획서 등) | 양식 번호 체계(`1.` `가.`) 유지 → lint에 `--allow-numbered` |

| 유형 | 제목 끝말 | 골격(순서대로) |
|------|-----------|----------------|
| 사업 계획(안) | `계획(안)` | 추진 배경 → 현황 및 문제점 → 사업 개요 → 사업 추진 계획 → 기대효과 |
| 추진 계획 보고 | `추진 계획` | 추진 배경 → 사업 개요 → 주요 내용(개선 사항) → 성과목표 및 추진 일정 |
| 검토 보고 | `검토 결과 보고`·`검토 보고` | 검토 개요(배경·요청 사항) → 현황 및 쟁점 → 대안 검토(대안별 장단점·비용) → 검토 의견(권고안) → 향후 조치 |
| 결과 보고 | `추진 결과`·`결과 보고` | 사업 개요(근거 문서 포함) → 추진 실적 → 성과 분석(통계·만족도) → 성과 및 향후 계획 |
| 상황 보고 | `(상황) 보고` | 개요 → 사실 경과(시각순) → 원인·영향 → 조치 사항 및 향후 대책 |
| 회의 결과 보고 | `회의 결과` | 회의 개요(일시·장소·참석자·안건) → 안건별 논의 요지·결정 사항 → 후속 조치(담당·기한) |
| 행사·평가 계획 | `계획` | 추진 배경(근거 문서) → 개요(일시·장소·대상·위원) → 세부 운영 계획 → 행정 사항 |

- 검토 보고는 대안을 둘 이상 비교하고, 권고안 하나를 고른 이유를 적는다. 대안이 하나뿐이면 "현행 유지"를 비교 대안으로 둔다.
- 결과 보고는 계획 대비 실적을 대조한다. 계획서의 목표 지표가 있으면 `목표 → 실적 → 달성 여부`를 표로 쓴다.
- 상황 보고는 확인된 사실과 추정을 나눈다. 추정은 `※`로 내리고 "추정"이라고 적는다.

형태·유형이 불분명하면 같은 부서의 기존 보고서를 따른다. 표에 없는 유형과 날짜·부서 줄 변형은 기관 관행 문서(있으면)를 따른다.

## 2. 기호 체계 (R1·R2)

`□` > `○` > `-` > `※`. 번호(`1.` `2.`)는 쓰지 않는다. 계획서형의 장 제목(Ⅰ~Ⅴ)은 표 머리 서식이며 `□`의 상위다.

- `□`: 장 안의 소제목. 계획서형 Ⅳ장처럼 하위 주제가 둘 이상이면 `□`로 나눈다.
- `○`: 한 문장 한 사실. 본부가 배포한 서식의 `◦`는 `○`와 같은 단계다. 서식을 채울 때는 `◦`를 유지한다.
- `-`: `○`의 세부. 1쪽 보고형에서 `□` 바로 아래 `-`는 허용(lint WARN).
- `※`: 근거 수치·출처·예외. 어느 단계에도 붙는다.
- `*`/`**`: 본문 용어의 각주 설명. `※`와 섞지 않는다.

## 3. 장별 내용 규칙

| 장 | 규칙 |
|----|------|
| 추진 배경 | 정책·환경 변화 → 직전 사업 결과 → `⇒` 결론 1줄. 결론에서만 "필요" 표현을 쓴다 |
| 현황 및 문제점 | `□ 현황` / `□ 문제점`으로 나눈다. 사실만 적고 대안·당위("~할 필요가 있음", "강화해야")는 쓰지 않는다(R3). 문제점은 `(표지) 사실` 형태 |
| 사업 개요 | 사업명·목적·대상·기간·예산·관련 정책 등. 계속 사업이면 목적 첫머리에 "YYYY학년도 「직전 사업명」을 이어받는 연속 사업"을 적는다 |
| 사업 추진 계획 | 현황·문제점의 각 문제에 대응하는 `□`를 하나 이상 둔다. 마지막 `□`는 "향후 추진 계획" |
| 향후 추진 계획 | 근거 실적의 연도를 적는다: "2026학년도 이용 실적과 만족도를 근거로 2027학년도 본예산에 반영"(R6) |
| 기대효과 | 사업 운영 지표(건수·만족도)를 반복하지 않는다. 관련 정책·대학 발전계획·평가 대응 등 상위 목표에 이 사업이 주는 효과를 쓴다. `(표지) 효과` 형태 3~4개 |

## 4. 관련 정책 인용

- 항목명은 "관련 정책 등"을 쓴다("정책 연계" 아님).
- 정책명·발표일·인용 문구는 발표 원문(부처 보도자료)에서 확인한다. 문서에 이미 적힌 날짜도 다시 확인한다.
- 기대효과에서 정책을 인용할 때는 원문 문구를 작은따옴표로 옮기고, 이 사업과의 연결을 한 문장으로 쓴다.

## 5. 문장·표기 (R4·R5)

- 개조식 종결: 명사형(`~운영`, `~구축`, `~발생 가능`)이 기본이고, 판단·상태는 `~함`, `~음`, `~임`, `~됨`으로 쓴다. 한 `□` 안에서는 종결 방식을 섞지 않는다. 경어체(`~습니다`) 금지.
- 날짜: `2026. 9. 21.`(연·월·일 글자 대신 온점, 0 붙이지 않음), 기간 `2026. 10. 15. ~ 2027. 5. 14.(7개월)`. 1쪽 보고형 요약 일정은 `’26. 9.` 허용.
- 요일: `2026. 8. 28.(금)`. 요일은 달력과 맞춘다(R7).
- 시각: 24시각제 `14:00`, `09:30`(R8). `오후 2시`·`14시` 금지.
- 금액: 본문 `총 60,935,000원(금육천구십삼만오천원)`, 표 `(단위: 천원)`.
- 법령·사업명·행사명: 홑낫표 `「 」`. 근거 문서는 `부서-문서번호(2026. 6. 16.) “제목”` 순서로 쓴다(문서 제목은 겹따옴표).
- 쌍점: 앞은 붙이고 뒤는 한 칸 띄운다(`사업 기간: 2026. 10. 15.`).
- 비율: 분모를 함께 적는다(`190명 중 19명(10.0%)`). 분모 없는 %는 쓰지 않는다.
- 범위어: `이상·이하·이전·이후`는 기준을 포함하고 `초과·미만`은 포함하지 않는다. 기준 포함 여부가 판단에 걸리면 이 구분을 지킨다.
- 같은 대상·기간·금액은 표지·요약·본문·표에서 같은 표기로 쓴다.
- 수치는 원문(설문 결과·관리자 콘솔·수요조사 집계)에서 가져오고 기준일을 `※`로 적는다.

## 6. 볼드

각 `○` 문장에서 판단에 필요한 핵심 1곳을 굵게 한다: 수치, 기간, 예산 총액, 결론 문구, 인용 정책 문구. 문장 전체를 굵게 하지 않는다. `(표지)`는 항상 굵게 한다.

수정안을 보여 줄 때는 굵게 할 문구를 마크다운 `**…**`로 표시한다. 여는 `**`만 있고 닫는 `**`가 없으면 R13 FAIL이다. 각주 기호(`Team**`, `** 설명`)는 해당하지 않는다.

## 7. 항목 문장 (R9~R11)

- **한 항목 한 내용.** `○` 하나에 사실 하나를 쓴다. 두 사실을 `~했으며`로 잇지 말고 `○` 또는 `-` 두 개로 나눈다.
- **길이.** 항목은 2줄(약 80자) 안에 쓴다(R10 WARN). 넘으면 세부를 `-`로, 근거·출처를 `※`로 내린다.
- **라벨.** 문제점·개선 사항·기대효과는 `(라벨) 내용` 형태로 쓴다. 라벨은 2~10자 명사구다.
- **과도한 압축 금지.** 조사·어미를 지나치게 줄여 뜻이 흐려지면 안 된다: `계획을 수립, 시행` → `계획을 수립하여 시행`. 필요하면 `다만`·`특히` 같은 접속어로 잇는다.
- **수사 금지(R9).** 물음표·느낌표·`~것이다`·대구·슬로건을 쓰지 않는다. 사실과 판단만 쓴다.
- **모호어(R11 WARN).** `적극`, `최대한`, `만전`, `가능한 한`은 구체적인 행동·수치·기한으로 바꾼다. 예: `적극 협조` → `2026. 10. 10.까지 명단 제출 요청`.
- **과장 금지.** 끝나지 않은 일에 `완료`를 쓰지 않는다. `실시간`·`비용 없음`·`획기적` 같은 말은 근거가 있을 때만 쓴다. 대책의 효과를 부풀리지 않는다.
- **쉬운 말.** 일반화되지 않은 약어·전문용어는 풀어 쓰거나 처음 나올 때 괄호로 설명한다. 외국어는 우리말을 먼저 쓰고 괄호에 병기한다.

## 8. 제출 전 점검표

A2 초안과 B2 수정안을 보여 주기 전에 아래 항목을 점검하고, "아니요"인 항목은 고치거나 완료 보고에 적는다. lint가 판정하지 못하는 항목이다.

| # | 점검 항목 |
|---|-----------|
| C1 | 첫 `□`(또는 요약)만 읽어도 결론과 요청 사항(결재·결정·인지)을 알 수 있는가 |
| C2 | 제목이 구체적인가(`~현황`·`~관련` 대신 무엇을 하는지가 보이는가) |
| C3 | 문제점마다 대응하는 추진 계획(또는 대안)이 있고, 문제점 없는 대책은 없는가 |
| C4 | 문제의 원인을 적었는가(현상만 나열하지 않았는가) |
| C5 | 모든 수치에 출처·기준일이 있고, 비율에 분모가 있는가 |
| C6 | 같은 대상·기간·금액이 문서 전체에서 같은 표기인가 |
| C7 | 예산·일정·담당(인력)이 계획 유형에서 빠지지 않았는가 |
| C8 | 관련 부서·이해관계자의 입장이 반영되었는가(한 부서 시각만이 아닌가) |
| C9 | 개요·요약과 본문 내용이 서로 맞는가 |
| C10 | 핵심 내용이 붙임으로만 넘어가지 않고 본문에서 완결되는가 |
