# 보고서 작성·수정

개조식 보고서를 쓰거나 고친다. 규칙 본문은 `references/style-rules.md`, hwpx 편집 조각은 `references/hwpx-recipes.md`에 있다.

```bash
SKILL_DIR="<absolute parent directory of the loaded SKILL.md>"
LINT="$SKILL_DIR/scripts/lint_report.py"
HWPX_DIR="$SKILL_DIR/../hwpx"
[[ -r "$LINT" && -r "$HWPX_DIR/scripts/validate.py" ]] || { echo "report-draft or hwpx scripts missing under $SKILL_DIR/.." >&2; exit 1; }
```

## 모드 분기

| 모드 | 언제 | 절차 |
|------|------|------|
| A. 작성 | 새 보고서가 필요할 때 | Step 1 → A1~A3 → 공통 게이트 |
| B. 수정 | 기존 보고서 hwpx를 고칠 때 | Step 1 → B1~B3 → 공통 게이트 |

## Step 1: 형태 판정과 근거 수집

1. `references/style-rules.md`를 Read한다. 사용자·호출 스킬이 기관 관행 문서를 주면 함께 Read하고, 둘이 다르면 기관 관행 문서를 따른다.
2. 형태(계획서형 / 1쪽 보고형 / 기관 서식형)와 유형(계획·검토·결과·상황·회의·행사)을 판정한다(규칙 §1). 기관이 배포한 서식이면 서식의 고정 골격을 유지하고 칸만 채운다.
3. 보고 대상과 요청 사항을 정한다: 누가 읽고(기관장·위원회), 무엇을 해야 하는가(결재·결정·인지). 요청에서 드러나지 않으면 유형으로 추정하고 골격과 함께 확인받는다.
4. 근거를 모은다: 사용자가 가리킨 노트·기존 보고서·조사 결과. 수치는 원문에서 가져오고 기준일을 적어 둔다.
5. 관련 정책을 인용하면 부처 발표 원문으로 정책명·발표일·문구를 확인한다(WebSearch/WebFetch). 문서에 이미 적힌 날짜도 다시 확인한다.

근거를 못 찾은 수치·날짜는 쓰지 않고 `[확인 필요]`로 남긴다. 추정하거나 지어낸 수치는 넣지 않는다.

## A. 작성

- **A1 골격.** 유형별 골격(규칙 §1)에 장·`□` 제목과 결론 한 줄(첫 `□` 또는 요약에 들어갈 문장)을 채워 보여 준다. 보고 대상·요청 사항 추정도 함께 적는다.
- **A2 초안.** 승인된 골격으로 본문을 scratchpad의 `.txt`에 쓴다(한 줄 한 문단, 기호 포함). 볼드 대상은 `**…**`로 표시한다. G1·G2를 통과시키고 점검표(규칙 §8)를 확인한 뒤 보여 준다. 점검표에서 "아니요"인 항목은 초안 아래에 적는다.
- **A3 hwpx.** 승인되면 Skill 도구를 "prod:hwpx"로 호출해 만든다. 같은 부서의 기존 보고서가 있으면 그 파일을 스타일 참조로 쓴다(Workflow 5, 원본 `header.xml` 재사용). 없으면 `report` 템플릿을 쓴다.

## B. 수정

- **B1 추출.** Skill 도구를 "prod:hwpx"로 호출해 본문을 추출하고 `python3 "$LINT" <원본.hwpx>`를 실행한다. lint FAIL은 요청 여부와 관계없이 수정안 후보로 올린다.
- **B2 수정안 먼저.** 요청 항목별로 "현재 → 수정" 텍스트를 보여 준다. "점검해 줘"처럼 범위가 넓은 요청이면 lint FAIL → 점검표(규칙 §8) "아니요" → lint WARN 순으로 우선순위를 매겨 보여 준다. 볼드 대상은 `**…**`. 사실 오류(날짜·수치)를 발견하면 따로 적고 수정 여부를 묻는다. 저장 방식(새 파일 권장)도 이때 묻는다. 수정안 문장은 G2를 통과한 것만 보여 준다. 승인 전에는 파일을 만들지 않는다.
- **B3 반영.** `references/hwpx-recipes.md` 순서대로 편집한다. 원본은 덮어쓰지 않고 `<원본명>_수정.hwpx`로 저장한다.

## 공통 게이트

| # | 게이트 | 통과 기준 |
|---|--------|-----------|
| G1 | `python3 "$LINT" <파일>` (기관 서식형은 `--allow-numbered`) | exit 0. WARN(R2·R10~R12)은 고칠 수 있으면 고치고, 남기면 이유를 보고 |
| G2 | Skill 도구를 "prod:kr-style"로 호출해 윤문 | 감사 스크립트 exit 0 |
| G3 | `python3 "$HWPX_DIR/scripts/validate.py" validate <결과> --baseline <원본>` (A는 `--baseline` 생략) | VALID |
| G4 | 한글로 열기 | 창 제목이 파일명(`빈 문서` 아님) |

G2 절차:

1. 사용자에게 보여 줄 한국어 본문(초안 또는 수정 문장)을 scratchpad 파일로 저장한다.
2. kr-style 루프를 돌린다: 감사 → `[FAIL]` 교정 → 수동 체크리스트 → 재감사.
3. exit 0이 된 문장만 보여 주고 hwpx에 넣는다. 감사 전 문장을 먼저 보여 주지 않는다.
4. 교정은 표현만 바꾼다. 사실·수치·판단과 개조식 종결(`~함`, `~음`, `~임`)은 유지한다.
5. 오탐(인용한 정책명·사업명·법령명, 원문 그대로 옮긴 문구)은 고치지 않고 완료 보고에 한 줄로 적는다.

B 모드에서 요청 범위 밖의 기존 문장이 감사에 걸리면 고치지 않고 완료 보고에 목록으로만 적는다.
